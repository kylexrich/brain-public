## Layout

- `docs/tasks/YYYY-MM-DD/<slug>/` - active task artifacts.
- `docs/tasks/YYYY-MM-DD/completed/<slug>/` - completed task artifacts.
- `docs/tasks/archived/` - archived task artifacts when a previous workflow already grouped them that way.

Historical casing such as `Completed/` may exist. Preserve it unless a separate cleanup task normalizes and rewrites exact references.

New task artifact shape is generated by the `$task-planning` (`/task-planning`) skill and its templates:
`{.ai,.claude,.codex}/skills/task-planning/SKILL.md` and `{.ai,.claude,.codex}/skills/task-planning/STEPS_TEMPLATE.md`.

## Task Artifacts Are Historical Evidence

Task docs under `docs/tasks/` record planning and execution context. They may be cited as supporting evidence, but current product, architecture, operations, and code truth remains in current source-of-truth docs and implementation. Active task docs govern execution of that task only.

## Keep Durable Truth Out Of Task Plans

When a task discovers durable product behavior, architecture, operations, or package guidance, extract the durable fact into the appropriate current doc and link back to the task artifact.

Exclude `docs/tasks/` from current-product doc-alignment by default. Include task docs only when the user explicitly asks to validate or edit task artifacts, or when updating the active task plan for the current work.

## Do Not Delete Historical Task Files

Preserve existing task artifacts. If task material is obsolete, mark it historical or move it within the task archive; do not delete it during documentation cleanup.
